**গল্প:** করিম ভাই মালিক, তাই অ্যাডমিন। কিন্তু তিনি প্রতিদিন অর্ডার লেখেন না। রোজের কাজের জন্য তাঁর একটা সাধারণ ইউজার থাকা উচিত, আর অ্যাডমিন লগইন শুধু সেটআপ/সমস্যার সময়।

## দুই স্তরের অ্যাডমিন

**Users → ইউজার → Access Rights → Administration** অংশে:

| চেকবক্স | মানে |
| --- | --- |
| **Settings** | সব অ্যাপ ইনস্টল/সেটিংস বদলাতে পারে — আসল "Administrator" |
| **Access Rights** | আরও গভীর টেকনিক্যাল অনুমতি (Developer Mode-এ দেখা যায়) |

## অ্যাডমিন দেওয়ার ধাপ

1. Users → করিমের ইউজার → Access Rights
2. Administration → **Settings** টিক
3. Save → লগআউট করে আবার লগইন
4. দেখো Settings মেনুতে সবকিছু খোলা

## স্বাস্থ্যকর অভ্যাস

| অভ্যাস | কারণ |
| --- | --- |
| সর্বোচ্চ **২ জন** অ্যাডমিন | একজন লকআউট হলেও অন্যজন উদ্ধার করবে |
| রোজের কাজে **সাধারণ ইউজার** | ভুলে সেটিংস বদলানো/ইনস্টল হয়ে যাওয়া ঠেকাতে |
| অ্যাডমিন পাসওয়ার্ড শেয়ার নয় | প্রত্যেকের নিজের লগইন |
| বদলানোর আগে **ব্যাকআপ** | Settings-এর ভুল বড় ক্ষতি করে |

## চাকরি ছাড়লে — অফবোর্ডিং চেকলিস্ট

| ধাপ | কোথায় |
| --- | --- |
| ১. ইউজার Archive | Users → Action → Archive |
| ২. পাসওয়ার্ড বদলানো | ইউজার ফর্মে নতুন পাসওয়ার্ড সেট |
| ৩. Portal এক্সেস বাতিল | Contacts → Action → Revoke Portal Access |
| ৪. Groups থেকে সরানো | গ্রুপের Users তালিকা থেকে বাদ |
| ৫. অর্ডার/ইনভয়েস হস্তান্তর | খোলা রেকর্ডের Salesperson/Responsible বদলাও |

## অ্যাডমিন লকআউট হলে

> `admin_passwd` (ডেটাবেস ম্যানেজারের মাস্টার পাসওয়ার্ড) আর লগইন পাসওয়ার্ড এক নয় — এটা দিয়ে লগইন করা যায় না।

দ্বিতীয় অ্যাডমিন থাকলে সে পাসওয়ার্ড রিসেট করতে পারবে। একদমই কেউ না থাকলে সার্ভারে Odoo shell দিয়ে:

```bash
cd ~/my-odoo
source venv/bin/activate
python3 odoo/odoo-bin shell -c odoo.conf -d YOUR_DB
```

```python
env['res.users'].browse(2).write({'password': 'NewStrongPass!'})
env.cr.commit()
```

(ইউজার আইডি ২ সাধারণত admin।) তারপর লগইন করে পাসওয়ার্ড বদলে নাও।
