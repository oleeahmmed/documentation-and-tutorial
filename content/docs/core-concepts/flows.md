## ধাপ ১৫: Flows

### বাস্তব গল্প (রূপসী ফ্যাশন)

রূপসী ফ্যাশনের ব্যবসা আরও বড় হলো। এখন শুধু “রফিক → সুমন → নাদিয়া” এই একটা টিমের কাজ চালালেই হয় না — পুরো প্রক্রিয়াটা আরও বড়।

করিম ভাই এখন চান এরকম একটা পুরো প্রক্রিয়া:

1. প্রথমে পুরো ডিজাইন-টিম (রফিক-সুমন-নাদিয়া) কাজ করবে, পোস্ট তৈরি হবে
2. এরপর **করিম ভাই নিজে** (কোনো টিম-সদস্য না, তিনি নিজেই) সেই পোস্টগুলো দেখে একটা সিদ্ধান্ত নেবেন — “পোস্টের ভাষা যদি বেশি রঙিন/উজ্জ্বল শব্দ ব্যবহার করে থাকে, তাহলে Instagram-এ আগে দেব, নাহলে Facebook-এ আগে দেব”
3. তারপর সেই সিদ্ধান্ত অনুযায়ী পরের ধাপ চলবে

লক্ষ্য করো — এখানে ধাপ ২-এ যেটা হচ্ছে, সেটা কোনো “কর্মীর কাজ” না, এটা করিম ভাইয়ের নিজের একটা সাধারণ নিয়ম/হিসাব (if-else-এর মতো একটা সিদ্ধান্ত)। একটা টিম (Crew) দিয়ে পুরো ব্যাপারটা ঠিক ধরে না, কারণ মাঝখানে করিম ভাই নিজে কোড-এর মতো একটা যুক্তি প্রয়োগ করছেন।

তাই করিম ভাই একটা বড় “মাস্টার-প্ল্যান” বানালেন, যেখানে টিমের কাজ আর তার নিজের সিদ্ধান্ত — দুটোই ধাপে ধাপে জোড়া লাগানো আছে।

### CrewAI-তে এই একই জিনিস

এই “টিমের কাজ + নিজের কোড-ভিত্তিক সিদ্ধান্ত — দুটো মিলিয়ে একটা বড় প্রক্রিয়া” ধারণাটাকেই CrewAI-তে বলা হয় **Flow**। একটা Flow একাধিক Crew এবং সাধারণ কোড-ধাপ একসাথে জুড়ে দিতে পারে।

### কোড (নতুন ফাইল `flow_project.py`)

```python
from crewai.flow.flow import Flow, listen, start

class FashionFlow(Flow):

    @start()
    def run_design_team(self):
        # ধাপ ১: পুরো fashion_crew কাজ করবে
        result = fashion_crew.kickoff(inputs={"topic": "ঈদ ফ্যাশন কালেকশন ২০২৭"})
        self.state["posts"] = result.raw
        return result.raw

    @listen(run_design_team)
    def decide_platform(self, posts):
        # ধাপ ২: করিম ভাইয়ের নিজের সিদ্ধান্ত — সাধারণ কোড, কোনো Agent না
        if "উজ্জ্বল" in posts or "রঙিন" in posts:
            return "Instagram-এ আগে পোস্ট করা হবে"
        else:
            return "Facebook-এ আগে পোস্ট করা হবে"

flow = FashionFlow()
final_decision = flow.kickoff()
print(final_decision)
```

### কোড ব্যাখ্যা — নতুন কী এলো

- `@start()` → এখান থেকে Flow শুরু হয়। এখানে পুরো `fashion_crew`-টাই একটা ধাপ হিসেবে চলছে।
- `self.state["posts"]` → Flow-এর নিজস্ব মেমোরির মতো জায়গা, যেখানে এক ধাপের তথ্য আরেক ধাপে ব্যবহারের জন্য রাখা যায়
- `@listen(run_design_team)` → আগের ধাপ (`run_design_team`) শেষ হলে এই ধাপ চলবে, আর আগের ধাপের output সরাসরি প্যারামিটার হিসেবে (`posts`) পাওয়া যায় — অনেকটা Task-এর `context`-এর মতোই, কিন্তু এবার পুরো Crew-এর উপরে আরেক স্তরে

### বাস্তবে কী ঘটে

```text
ধাপ ১ (run_design_team) চললো:
fashion_crew পুরোপুরি কাজ করলো (রফিক → সুমন → নাদিয়া),
যার আউটপুট হলো:
"🎉 ঈদের রঙিন আনন্দে রূপসী ফ্যাশনের নতুন কালেকশন..." (৩টা পোস্ট)

ধাপ ২ (decide_platform) চললো:
posts-এ "রঙিন" শব্দটা পাওয়া গেলো
→ রিটার্ন হলো: "Instagram-এ আগে পোস্ট করা হবে"

flow.kickoff() এর ফাইনাল আউটপুট:
"Instagram-এ আগে পোস্ট করা হবে"
```

লক্ষ্য করো — এখানে করিম ভাইয়ের সিদ্ধান্তটা (`if/else`) কোনো AI Agent না, এটা সাধারণ পাইথন কোড। **Flow-এর মূল সুবিধা হলো — AI-চালিত কাজ (Crew) আর সাধারণ কোড-লজিক একসাথে মসৃণভাবে জোড়া লাগানো যায়।**

### এখন কী অবস্থা

এখন পুরো রূপসী ফ্যাশনের প্রক্রিয়া একটা Flow-এর ভেতরে — Crew-এর কাজ আর করিম ভাইয়ের নিজের সিদ্ধান্ত, দুটোই একই মাস্টার-প্ল্যানে ধাপে ধাপে চলছে।
