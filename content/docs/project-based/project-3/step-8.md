## লক্ষ্য

কোম্পানির আসল নিয়মগুলো একটা টেক্সট ফাইলে রাখা — এখান থেকেই নাদিয়া উত্তর খুঁজবে।

## ফাইল বানাও

নতুন ফাইল বানাও `knowledge/faq_policy.txt`:

```bash
cat > knowledge/faq_policy.txt << 'EOF'
## SMS ক্রেডিট ও বিলিং
- ডেলিভারি ফেইল করলে ২৪ ঘণ্টার মধ্যে স্বয়ংক্রিয়ভাবে ক্রেডিট ফেরত হয়।
- ২৪ ঘণ্টা পরও না হলে support@blastify.com-এ মেইল করতে হবে।

## রিফান্ড পলিসি
- আংশিক ব্যবহৃত প্যাকেজ রিফান্ডযোগ্য নয়।
- টেকনিক্যাল সমস্যায় কাটা ক্রেডিট সম্পূর্ণ রিফান্ডযোগ্য।

## সাবস্ক্রিপশন বাতিল
- ড্যাশবোর্ড থেকে যেকোনো সময় বাতিল করা যায়, কোনো ফি নেই।
EOF
```

**এটাই আসল জায়গা** — এটাই নাদিয়ার হাতে থাকা সেই নিয়মের খাতা, কোম্পানির চূড়ান্ত ও একমাত্র সত্য তথ্যের উৎস। যত ভালো তথ্য দেবে, নাদিয়া তত ভালো উত্তর দিতে পারবে।

> **Windows-এ `cat > ... << EOF` চলবে না** (PowerShell/CMD-তে heredoc নেই)। তখন এডিটরে `knowledge/faq_policy.txt` ফাইল বানিয়ে ভেতরে একই লেখা বসাও — ফলাফল একই।

## এই ফাইলে কী রাখবে

| রাখবে | রাখবে না |
| --- | --- |
| ছোট, স্পষ্ট নিয়ম (এক লাইনে একটা) | লম্বা মার্কেটিং লেখা |
| আসল পলিসি (রিফান্ড, বিলিং, বাতিল) | পুরোনো/বাতিল হওয়া নিয়ম |
| কে অনুমোদন দেয়, কত সময় লাগে | অনুমান বা ভবিষ্যতের পরিকল্পনা |

> **CrewAI knowledge কীভাবে পড়ে:** ফাইলটা ছোট টুকরো করে embedding বানিয়ে রাখে, পরে প্রশ্নের সাথে মিলিয়ে অংশ খুঁজে দেয়। তাই ডিফল্টে একটা embedding মডেল (OpenAI) লাগে। OpenAI key ছাড়া শুধু Groq/Gemini দিয়ে চালালে knowledge-এ এরর আসতে পারে — তখন OpenAI key যোগ করো বা knowledge বাদ দিয়ে আগে flow টেস্ট করো।

> ফাইল বদলালে পরের রানে নতুন তথ্য ব্যবহৃত হবে — কিন্তু আগের embedding cache থাকলে একবার রিফ্রেশ/নতুন করে চালাতে হতে পারে।
